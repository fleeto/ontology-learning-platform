## 架构判断

- 保留案例的纯计算数据包与通用呈现引擎，业务计算不进入图谱组件。
- 将案例状态转换抽为纯 reducer，界面禁用和状态转换均检查审批条件，支持独立回归验证。
- 工作流以当前步骤作为进度事实源，避免 completedSteps、对象高亮、效果数组互相漂移。审批策略直接引用模型定义。
- Workshop 的演示数据保持确定性；真实查询、保存、发布是不同能力，界面明确当前边界。
- 首页、案例和工作流的教学结构不同，本次没有强行合并为一个大组件。共享状态、模型和几何规则比整体重写风险更低。

## 验证

- `npm run verify:simulation`：参数重置、审批阻断、连续审批门、终点边界、负坐标及 suppliedBy 方向。
- `node --import tsx scripts/verify-cases.ts`：三个案例的边界参数与模型引用检查。直接使用 tsx loader 避免部分沙箱不允许 CLI IPC 管道的问题。
- `npm run build`：生产编译、类型检查及静态路由生成。
- 浏览器实际操作：软件工厂到审批门不能前进，批准后完成，再改复杂度回到第一步；工作流采购、改线和到货确认；模型要求的声明中断审批；首页节点 Enter 选中；Workshop 预览隐藏编辑控件、切换操作、新增关系组件。
- 首页截图检查：概念说明、阶段和输入输出区域层次清晰。此次未做完整移动端与辅助技术兼容性认证。

## 范围与限制

这是教学演示审查，重点为首页、三个案例的共享引擎、工作流、组装台及其模型。数据源、管道、建模页进行了结构性检查，未对每个交互穷举验收；外部案例来源真实性与依赖安全升级不在本次验证结论中。

所有审批与执行仍在浏览器内模拟，刷新会清除状态；Workshop 的筛选/排序配置仅说明意图，未接入查询引擎。真实 ERP、服务端授权、持久化审计与部署服务属于未来产品化工作，不应由当前前端演示暗示已经完成。
